Monitoring · AI scoring · Alerts

Daily job monitor with LLM scoring

Pulls listings from multiple sources every morning, deduplicates them, hard-filters by rules, then sends the rest to an LLM that scores each one for fit and writes a one-line reason. The top results land in Telegram as a single short digest.

  • Anti-bot handling: one source returns 403 to plain requests, so it routes through headless Chrome instead.
  • Cost control: the model kept exhausting its output budget on internal reasoning, so I disabled that and the responses became complete, faster, and cheaper.
  • Catch-up scheduling: if the machine is off at 8am it retries every two hours, with a guard so it only ever runs once per day.
n8n · headless Chrome · Gemini API · Telegram Bot API · cron
Pipeline · Scheduled digest

Web app to database to nightly report

A daily tracking web app writes snapshots to a realtime database. A scheduled job reads that data every night, formats it into a readable summary, and pushes it to Telegram. No manual export, no spreadsheet.

  • Deployed frontend, hosted database, and a scheduled worker, all wired together.
  • Idempotent writes so a refresh never duplicates a day's record.
Vercel · Firebase Realtime DB · GitHub Actions cron · Python · Telegram
Multi-agent · Context management

Multi-agent coordination with automatic compaction

Three AI agents collaborate through a single shared file as the source of truth. A file watcher wakes the right agent when the file changes. When the log grows too long, a compaction step archives the full history and rewrites it into a summary that keeps decisions and open tasks while dropping the noise.

  • Turn protocol with a hard round limit so the agents cannot loop forever.
  • Compaction backs up the original first, so nothing is ever lost.
  • Cut a 1,592-line log to 220 lines with no loss of decisions or open items.
Bash · file watcher · LLM CLI · structured summarisation
